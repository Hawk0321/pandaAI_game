# 像素素材生成与验收流程

> 2026-10-31 样张使用 `gpt-image-2.5` 通过 OpenAI 兼容 Images API 生成。
> 模型输出是构图母版，不直接宣称符合 64×64 / 16×16 像素规范；最终像素稿须经过本地后处理和人工验收。

## 1. 交付层级

```text
frontend/src/reigns/assets/
├── _source/       AI 高清构图母版，保留用于重做，不直接用于游戏
├── characters/    64×64 人物像素稿
├── avatars/       64×64 头像像素稿
├── icons/         16×16 图标、8×8 提示帧
└── endings/       128×96 结局像素稿
```

最终接入时从像素稿用最近邻整数放大，再导出 WebP。`_source` 不能作为
“像素原图”验收；避免用 `@2x`、`@3x` 冒充手绘原稿。每张素材登记模型、日期、
提示词、参考图、后处理和审核状态。

## 2. 生成顺序

1. **风格样张**：三个角色 neutral 头像、一个 NPC、一组 normal/low/high 图标。
   并排确认造型、色板和缩小后的辨识度后再批量生成。
2. **P0 人物**：以人物清单 2.2 为唯一基准；所有 neutral 先完成，再补关键表情。
3. **P0 图标和结局**：小尺寸图标优先直接像素绘制；AI 只提供构图参考。
4. **P1/P2**：提前 `sp-survivor`，再补齐特殊结局和低频表情。

## 3. 提示词与一致性

- 统一使用有限色板、清晰外轮廓、单主体、单色或极简背景；不要要求模型直接输出
  “真实 64×64”后就把高清结果当合规成品。
- 多表情必须用已审核 neutral 图为参考走编辑流程，只改眉眼嘴；仅替换提示词中的
  `Expression` 不能锁定角色身份。API 不保证跨请求固定 seed 一致。
- 头像和人物的单图上限是 16 色，不是公共模板里的 32 色；全局色板仍是 32 色。
- 不出现真实品牌、logo、可读文字或水印；“推特大 V”用原创手机与广播气泡表达。
- 内心独白使用不透明像素气泡轮廓和剪影，不使用模糊、半透明或渐变。

## 4. 本地后处理

`assets/pixelate.py` 是离线后处理工具，不读取或保存 API 密钥。它需要 Python 与
Pillow，通过全局 32 色色板进行 CIELAB 最近色映射，再检查单图色数：

```bash
uv run --with pillow python assets/pixelate.py _source/avatar-fund-neutral.png avatars/avatar-fund-neutral.png
```

自动量化只是第一轮，不替代修像素。描边、眼睛、道具、轮廓和低/高警示态必须逐张
检查；16×16 与 8×8 素材若缩小后不能辨识，改为手画，不靠反复生成碰运气。

## 5. API 与验收

- 密钥只从本地环境读取，不写入脚本、Markdown、日志或仓库；生成服务不得暴露给浏览器。
- 原稿与像素稿均不覆盖已审核文件；重做使用新版本文件名并登记原因。
- 验收包括：实际像素尺寸、单图色数、完全不透明/透明的 alpha、无抗锯齿、命名、
  缩略辨识度和文件体积。结局还要同槽位 low/high 并排检查。
- 图片是 AI 辅助生成的示例素材，提交 PR 时披露模型 `gpt-image-2.5`、生成日期
  及本地色板量化/人工修整情况。
