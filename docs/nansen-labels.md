# 参考 Nansen：从交易记录到标签，怎么用到画像模块（D）

> 调研 + 设计建议，给 nate 和 D 模块的 AI 读。只是方案，**还没有改任何代码**；要不要采纳、采纳哪几条由 nate 决定，代码归 D 模块（PR #8，`frontend/src/profile/`）。
> 调研时间：2026-10-30。来源见文末。Nansen 没有公开具体阈值和打分公式，下面凡是"Nansen 怎么做"都来自其公开文档，凡是推断都会标"推断"。

## 1. 一句话结论

Nansen 的标签本质上是"**按时间窗、按明确阈值、可失效的行为标签**"。最值得我们学的是它的**标签形态**（一条标签 = 一句定义 + 一个阈值 + 一组命中的交易）和**生命周期**（初现 / 正式 / 曾经）；最不能学的是它的**核心口径**（按收益排名评 Smart Money），因为这和我们"收益不能当能力唯一标准"的硬要求正好相反。

## 2. Nansen 的做法（调研摘要）

### 2.1 两类标签

| 类型 | 回答的问题 | 例子 | 来源 |
|---|---|---|---|
| 实体标签 | 这个地址**是谁** | 交易所热钱包、DEX 池合约、基金（Smart Fund）、公众人物、钓鱼地址、某机器人用户 | 链上启发式 + 地址聚类 + 公开信息 + 人工研究 |
| 行为标签 | 这个地址**怎么交易** | 30D/90D/180D/2Y Smart Trader、Emerging Smart Trader、Former Smart Trader、Exit Liquidity（"总是追高、进得晚"）、Sector/Chain Specialist、New Token Specialist、Memecoin Whale | 从交易记录算出来的规则 |

### 2.2 行为标签怎么算

- **Smart Trader：按时间窗内的收益排名取前 N 名。** 官方原文是 "Top-ranked wallets by PnL in past N days"，窗口有 30 天、90 天、180 天、2 年。还会看最低胜率、ROI、已实现利润、盈利代币数、跨行情周期的表现等，但**不公布具体数字**。短窗口要求更高的胜率、更低的利润门槛；长窗口反过来，并要求更分散。
- **很多标签是"占比 + 阈值"的明文规则。** 例如 New Token Specialist：过去 180 天已实现收益中 ≥65% 来自上线 2 天内买入的代币；Memecoin Whale：持有市值 > 3000 万美元的某个 meme 币超过 0.1% 的供应量；Token Millionaire：持仓 ≥ 100 万美元。
- **生命周期。** Emerging Smart Trader = 表现接近但规模不够；Former Smart Trader = 以前是、现在不再满足条件。标签随时间窗滚动重算，不是一次贴上永久有效。
- **会淘汰没用的标签。** 7-Day Smart DEX Trader 被永久下线，First Mover LP、Airdrop Pro 等被移出 Smart Money。推断：这些标签对"之后表现"的区分力不够。

### 2.3 用户怎么看懂标签

- 标签以小标签（部分带 emoji）出现在所有看板上；点地址进 Profiler 能看到收益、胜率、近期交易。
- **但 Nansen 不说明某个地址具体因为哪几笔交易、满足了哪个阈值而得到标签。** 这是它可解释性的短板。
- 竞品的批评（CoinMarketMan，有商业立场）：静态标签"比市场变得慢"，身份不等于能力，应改为按行为实时分组。

### 2.4 Nansen 也没公开的

具体阈值、刷新频率、置信度、有没有用机器学习，公开文档里都没有。所以我们只借鉴它的结构，阈值继续用我们自己在 `docs/profile.md` 里写明的规则。

## 3. 对照：哪些能用、哪些不能用

| Nansen 的做法 | 我们用不用 | 原因 |
|---|---|---|
| 实体标签 / 行为标签分两类 | **用**，对应"偏好 / 能力"分开，并再细分出"行为事实" | 我们的硬要求就是能力和偏好分开 |
| 一条标签 = 明文定义 + 阈值 + 命中记录 | **用**，新增"行为标签"一层 | 评委能直接看到"为什么给我这个标签" |
| "占比 ≥ X%" 的写法（如 ≥65% 的收益来自…） | **用**，改成"≥ 60% 的适用关卡出现该行为" | 比"出现过一次"稳，适合 4–5 关的小样本 |
| Emerging / Former 生命周期 | **用**，对应第 1 轮和第 2 轮画像 | 正好讲清补充关卡带来的变化 |
| 多时间窗（30D/90D/…） | **部分用**：只分"本局全部"和"最近两关" | 我们一局只有 4–5 关，分多个窗口没意义 |
| 跨行情周期的表现（在下跌中也行不行） | **用**，置信度要求证据覆盖不同行情类型 | 防止"只在上涨关里看起来会用线索" |
| 淘汰区分力差的标签 | **用**，用 3 组模拟玩家检验每个标签 | 3 组玩家都命中或都不命中的标签没有信息量 |
| Exit Liquidity（追高、进得晚） | **用**，变成偏好标签"追涨" | 可以从 `bars` 直接算，不看结果 |
| 按收益排名评 Smart Money | **不用** | 违反"收益不能当能力唯一标准"；我们没有玩家总体，也排不了名 |
| 胜率、ROI 作为能力门槛 | **不用**（只在揭晓页展示收益） | 同上；4 关的胜率几乎全是运气 |
| 地址聚类、链下身份、人工标注 | **不用** | 我们只有一个玩家一局的事件 |
| 和总体比"前 N 名" | **不用**；可选改为和 3 个 AI 对手（`bots`）对比 | 唯一现成的参照系是同一关的策略机器人 |

## 4. 给 D 的具体改动建议

按"值不值、花多少工夫"排序。1 和 2 是核心，3–5 是加分，6 可以不做。

### 建议 1：在证据和维度之间加一层"行为标签"（核心）

现在是 `证据 → 维度分数 → 人物卡`。分数（比如"风险控制 0.31"）评委不好直接理解。仿照 Nansen，加一层用人话写的**行为标签**：

```
事件 → 证据（已有） → 行为标签（新增，每个有定义、阈值、命中关卡） → 维度判断（已有） → 人物卡（已有）
```

建议的标签表（全部能用现有事件算，不看收益）：

| 标签 | 归属维度 | 每关判定（这关"命中"） | 适用关卡 |
|---|---|---|---|
| 🎯 关键线索猎手 | 证据使用 + | 翻开了全部 `key_clue_ids` | 有关键线索的关 |
| 🙈 只看想看的 | 证据使用 − | 现有"确认偏误"规则 | 翻了 ≥2 张的关 |
| 🎲 裸奔下单 | 证据使用 − | 一张线索没翻就入场 | 入场的关 |
| 🔥 信心爆棚 | 判断校准 − | 信心 ≥4 且方向错 | 可检验对错的关 |
| 🧊 心里有数 | 判断校准 + | 信心与对错的 Brier 分 ≥ 0.8 | 可检验对错的关 |
| 🪂 满仓无伞 | 风险控制 − | 半仓以上且没设止损 | 入场的关 |
| 🧯 果断止损 | 风险控制 + | 浮亏超 1% 时减仓或平仓，或止损被触发 | 出现浮亏的关 |
| ⛏️ 越跌越买 | 风险控制 − | 浮亏超 1% 时加仓 | 出现浮亏的关 |
| 🚀 追涨 | 风格（偏好） | 前 20 天涨超 10% 且价格在 60 日高点附近（≥ 最高价的 97%）仍做多（对应 Nansen 的 Exit Liquidity） | 满足"大涨后"条件的关 |
| 🔄 抄底 | 风格（偏好） | 前 20 天跌超 10% 时做多 | 满足"大跌后"条件的关 |
| ⚡ 秒决 | 研究深度（偏好） | `think_ms` < 8 秒且翻线索 ≤1 张 | 所有关 |
| 👀 观望派 | 风险偏好（偏好） | 选择观望 | 所有关 |

**标签成立规则**（借鉴 Nansen 的"占比 + 阈值"）：

- 正式标签：命中 ≥ 2 关，且命中关数 / 适用关数 ≥ 60%。
- 初现标签（对应 Emerging）：只命中 1 关，或占比在 34%–60% 之间。页面上用浅色显示"初现"，不进人物卡。
- 曾经标签（对应 Former）：第 1 轮是正式标签，第 2 轮不再满足。只在第 2 轮画像的"变化"里出现。
- 每个标签都带：一句定义（含阈值）、适用关数、命中关数、命中关卡和事件编号。页面点开标签就能看到"第 2、4 关满仓没设止损（共 3 关入场，命中 2 关）"。**这一点要比 Nansen 做得好**：它不告诉用户为什么得到标签，我们每个标签都能追溯到事件。

协议改动（只加可选字段，按 `docs/protocol.md` 第 8 节可以直接改，PR 标题加 `[协议]`）：

```ts
export interface BehaviorTag {
  id: string;                    // "naked_full_size"
  name: string;                  // "满仓无伞"
  emoji: string;
  dimension_id: DimensionId;
  direction: "+" | "-" | "pref"; // 对能力维度是加分还是减分；偏好标签为 "pref"
  rule: string;                  // "半仓以上入场却没设止损；≥2 关且占入场关 60% 以上即成立"
  applicable: number;            // 适用关数
  hits: { level_id: string; event_seqs: number[] }[];
  status: "active" | "emerging" | "former";
}
// Profile 增加：tags?: BehaviorTag[]
```

C 的画像页不用改也能继续工作；想展示时，在每个维度下面加一排标签即可。

### 建议 2：置信度加一条"行情覆盖"（核心，改动小）

Nansen 看 Smart Money 时要求"在不同行情周期都表现好"。我们现在的高置信度只看"≥3 关 + 一致性 ≥80%"。建议加一条：

- **高置信度还要求证据覆盖 ≥2 种行情类型**（`reveal.scenario`，如上涨和暴跌）。否则最多到中，并在 `uncertain` 里写"目前只在上涨行情里看到这个行为，不知道下跌时会不会变"。
- `pickNextLevel` 选补充关卡时，在 `probes` 匹配的关卡里**优先选没玩过的行情类型**。只是排序变化，函数签名不变。

注意：`scenario` 在 reveal 文件里，D 是在决定之后才用，不会把未来数据传给前端，符合信息隔离。

### 建议 3：第 2 轮用 Emerging / Former 讲"变化"（加分）

现在第 2 轮的 `changes` 是"判断文字之前 → 之后"。如果做了建议 1，可以额外写标签的变化，例如"🔥 信心爆棚：初现 → 正式"、"⛏️ 越跌越买：正式 → 曾经"。这比分数变化更容易在演示时讲清楚"补充关卡确实让我们更了解你"。不需要改协议，写进 `changes` 的 before/after 文本即可。

### 建议 4：人物卡改由"正式标签"驱动（加分）

现在人物卡由维度分数阈值决定。改成"由正式标签组合决定"后，人物卡的理由可以直接说"因为你有 🪂 满仓无伞 和 ⚡ 秒决 两个标签"，评委更容易接受。初现标签不参与，避免一关的偶然行为决定人物卡。可以保留现有 8 种人物卡，只换匹配条件。

### 建议 5：用模拟玩家淘汰没用的标签（加分，借鉴 Nansen 下线标签）

在 `samples.test.ts` 里加一个检查：每个标签至少在 3 组模拟玩家里**有区分**（不是 3 组全中，也不是 3 组都不中）。不满足的标签要么改阈值，要么删掉。这样能在 `docs/profile.md` 里说"每个标签都经过区分力检验"。

### 建议 6：和 AI 对手比，代替排名（可选）

Nansen 靠"在全体中排前 N"定义 Smart Money，我们没有全体。唯一的参照系是每关的 3 个策略机器人（`bots`）。可以在**揭晓页或画像页**展示"你的方向和双均线 / 海龟 / 均值回归哪个更像"，作为风格偏好的辅助证据（例如 4 关里 3 关和海龟突破同向 → 支持"趋势"）。**不要**用"你比机器人赚得多"来评能力。

## 5. 明确不做的

- 不按收益、胜率给能力打分或排名（违反评分硬要求，样本也太小）。
- 不做多时间窗（30/90/180 天）的并行标签，一局只有 4–5 关。
- 不做身份类标签（基金、机构），我们没有身份数据，也不该推测。
- 不引入机器学习：Nansen 公开资料也没说用了，而我们没有训练数据。
