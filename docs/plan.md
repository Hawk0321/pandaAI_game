# 一天开发计划与分工

> 给 4 个人和各自 AI 用的总纲。这里只定方向、边界和接口，具体实现交给各自的 AI。

## 做什么

手机打开的 H5 小游戏，5 分钟玩完：

1. **看盘**：一段隐去名称和日期的真实历史 K 线（来自 Panda Data），截在关键位置。
2. **查线索**：用有限的研究点翻线索卡（成交量、大盘、资金面等）。
3. **下决定**：做多 / 做空 / 观望，选仓位和信心。
4. **揭晓**：显示后续走势、真实标的，以及几个简单策略（双均线、海龟等）的表现。
5. **画像 → 推荐 → 下一步**：玩完 4–5 关后，给出有证据的画像（能力和偏好分开），以及因人而异的推荐和能马上动手的下一步。证据不够时加一关补充关卡。

## 架构

```
backend/scripts（Python，离线跑） ──Panda Data──▶ 关卡 JSON（可见部分 / 揭晓部分 分两个文件）
                                                      ▼
frontend（纯静态 H5，浏览器里跑完全部逻辑）：游戏 → 行为日志 → 画像 → 推荐 → 结果页
```

- 不做常驻后端，前端部署成静态网站（GitHub Pages / Vercel），评审期间不会挂。
- 前端不直接调 Panda Data，凭证只在跑脚本的电脑上用环境变量。
- 揭晓部分只在玩家提交决定后才加载（信息隔离）。

## 四个接口

各模块只通过这四种 JSON 交流。每种先在 `data/samples/` 放一份示例，大家先对着示例开发，互不等待。

| 接口 | 谁产出 → 谁使用 | 大致内容 |
|---|---|---|
| 关卡 Level | A → B | 可见 K 线、线索卡、关键线索、行情标签；揭晓文件里放后续走势、真实标的、策略表现、数据来源 |
| 行为事件 Event | B → C | 每个动作一条：翻了哪张线索、决定、仓位、信心、用时 |
| 画像 Profile | C → D | 每个维度：判断、证据、置信度、还不确定什么（格式见 `README.md`） |
| 推荐 Recommendation | D → 结果页 | 推荐的资源、理由、下一步 |

接口格式由 nate 在开场 1 小时内定下，之后要改先在群里说。

## 分工

| 人 | 负责 | 目录 | 一天结束时要有 |
|---|---|---|---|
| **nate** | 搭项目骨架、定接口、画像规则、合并和部署 | `frontend/src/profile`、整体 | 能跑通的线上链接；画像能力/偏好分开、有证据和置信度 |
| **A** | 数据与关卡 | `backend/` | 6–10 个真实关卡 JSON；`docs/panda-data.md` 写清用的接口、字段和时间口径 |
| **B** | 游戏界面 | `frontend/src/game` | 手机上能玩完看盘 → 线索 → 决定 → 揭晓，并输出行为事件 |
| **C** | 推荐、结果页、演示材料 | `frontend/src/recommend` | 资源清单、匹配规则、结果页和人物卡；两条演示路径、项目说明草稿 |

原则：每人只改自己的目录；共享的东西（接口、样式）找 nate。

## 时间线（一天）

| 时间 | 目标 |
|---|---|
| 开场 1 小时 | nate 搭好前端骨架、放好四份示例 JSON、部署出链接；其他人读本文件和 `README.md` |
| 上午结束 | 各自模块对着示例跑通 |
| 午后第一次合并 | 用示例数据把整条链串起来，手机能打开 |
| 下午 | 换成真实关卡；画像和推荐规则做完；补充关卡 |
| 傍晚 | 打磨界面；跑两条不同路径；录 3–5 分钟视频；补项目说明和来源披露 |

## 给各自 AI 的开场话（复制后补上你的角色）

> 请先阅读仓库里的 `AGENTS.md`、`README.md` 和 `docs/plan.md`。我负责其中的【A 数据与关卡 / B 游戏界面 / C 推荐和结果页】。只改我负责的目录，按 `data/samples/` 里的示例 JSON 对接，不要改接口格式。先做出最简单能跑的版本，再逐步完善。完成后按 `docs/team-guide.md` 开 PR。

## 底线（评分硬要求）

- 未来数据不能提前出现在前端可见部分。
- 画像能力和偏好分开，收益不是能力的唯一标准，每个判断能追溯到具体行为。
- 示例数据、示例资源、没做完的功能都要标注。
- 不提交任何密钥。用到的第三方库和 AI 工具在 PR 里写明。
